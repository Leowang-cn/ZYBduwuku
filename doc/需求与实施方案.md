# 团队软件中心与方案社区｜需求与实施方案

## 1. 项目目标与范围

建设仅面向 PC 浏览器的内部软件服务门户，整合软件目录、版本交付、私密反馈、审核式知识社区及后台管理。前端采用 React、TypeScript、Mantine 官方组件与统一暗色主题；不依赖运行时 CDN。FastAPI 提供 API 和生产环境前端静态托管；SQLite 存储业务数据，大文件使用 MinIO（S3 兼容）或开发环境项目内文件目录。

## 2. 角色与公开页面

### 2.1 匿名访问者
- **软件中心**：全文关键字段搜索、分类筛选、精选标记、软件卡片及产品详情；展示名称、简介、介绍、截图、分类、来源（自研/第三方）、开发团队、独立子应用、版本历史、变更说明与各版本交付物。
- **交付物**：一个版本支持多个安装包或外链；浏览器扩展 ZIP、HTML ZIP 等仅作为普通附件存储，绝不解压、扫描执行或运行。只含 URL 的版本同样有效，不强制要求文件。站内文件下载请求和外链跳转点击分开统计，不能将请求计数称为下载完成。
- **用户反馈**：可匿名给软件提交文本意见；反馈仅后台管理员可见，不在公共 API 泄露。
- **方案社区**：公开审核通过的方案；按分类浏览，查看作者显示名、正文、关联软件、附件与回复；可匿名回复并选择显示名。公众不可修改或删除投稿、回复。
- **投稿**：填写标题、正文、分类、可选软件、可选显示名与附件；提交后进入审核队列。待审核内容与附件不出现在公开列表或详情；审核通过后才可公开。驳回原因仅管理员可见。
- **使用指南**：管理员撰写并公开发布的文章。

### 2.2 管理员
独立登录/退出、修改密码；管理概览及 14 日下载请求/外链点击趋势；产品与子应用 CRUD、版本及交付物、截图上传、分类、精选及发布状态；方案审核、按理由驳回、删除方案和回复；查看/删除私密反馈；指南文章 CRUD；修改密码。

## 3. 数据与业务规则

- SQLite 采用外键、级联清理与 WAL；实体包括管理员设置、分类、软件、子应用、版本、交付物、截图、反馈、方案、附件、回复、指南文章及资源请求事件。
- 软件可以单独发布，不要求必须有关联版本；版本可以只有 URL。未公开产品不能对外暴露，已发布产品的下载由服务端校验。URL 仅接受 HTTP(S)。
- 方案状态为待审、通过、驳回；正文/附件隔离在同一应用权限控制后，公众只能读取通过状态。作者名默认匿名；回复记录服务端接收的客户端地址，并在公开回复中展示该地址（默认是直连地址；仅在明确配置可信代理网段时才从可信 `X-Forwarded-For` 链解析）。
- 默认启动不创建演示数据；需要演示数据时显式设置 `SEED_DEMO_DATA=true`（生产环境禁止该设置）。
- 产品平台与交付形式分类由后台维护并用于筛选；版本号可为空，纯 URL 交付不强制版本。图片可直接展示，视频提供在线播放控件；文章支持编辑、发布与取消发布；反馈支持最多 5 张截图和管理员“已处理”状态。

## 4. 文件、上传和安全要求

- 文件唯一持久化到私有 MinIO；生产及开发运行均必须配置 MinIO endpoint、凭据、桶名与 TLS。文件上传仅写入短暂 `.upload-staging/` 目录，成功或失败后立即清理；SQLite 只保存对象键和业务元数据。MinIO 桶不得配置公开策略；下载由后端校验已发布产品后签发 5 分钟短期预签名 URL，外链和对象下载均分别统计。
- 所有上传先检查扩展名、数量及大小：产品附件至多 100 MB（同时受全局限制），方案附件每份至多 50 MB、每次至多 5 份；产品截图只接受 PNG/JPEG/WEBP/GIF；方案接受图片、视频、PDF、ZIP、纯文本/Markdown。配置 `MAX_UPLOAD_MB` 可统一设定更低上限。禁止路径穿越，存储名称由服务端随机生成。ZIP 永不展开执行；文件通过附件下载响应而非项目静态目录直接访问。
- 使用 SQLite 持久化管理员密码的加盐 PBKDF2-HMAC-SHA256 哈希；旧版无盐 SHA-256 仅在成功登录时兼容并立即升级。环境变量只负责首次创建管理员账户，不向仓库写入秘密。生产需使用足够随机的 `SECRET_KEY`，否则后台 cookie 不可安全认证。
- 登录及匿名投稿、回复、反馈有按客户端 IP 的应用级频率限制；输入长度及上传类型有服务端校验。后台 cookie 为 HttpOnly、SameSite Strict；管理写请求使用 CSRF Cookie/Header 双提交检查。HTTPS 部署设置 `COOKIE_SECURE=true`。
- Markdown 先转义 HTML，再仅渲染有限的格式（标题、链接、强调、代码），阻止原始 HTML 注入。外链新标签使用 `noopener noreferrer`。
- 所有前端资源随构建输出部署，不需 CDN。健康接口为 `GET /api/health`；监听 `0.0.0.0`，端口由 `PORT` 决定。

## 5. 部署、配置和运维

本项目使用 SQLite 保存业务元数据，不复用机器上其他 PostgreSQL/Redis；所有上传对象唯一持久化到私有 MinIO，项目本地 `.upload-staging/` 仅作自动清理的临时中转，不能用作持久化或备份。`data/` 必须持久化并纳入备份、排除源码版本控制。环境变量名与部署约束、版本查询、健康检查、Procfile、备份恢复等见 [`../docs/部署要求.md`](../docs/部署要求.md) 及仓库根目录 `.env.example` / `README.md`。部署时构建 `npm run build`，Procfile 使用 Uvicorn ASGI 服务；生产安装依赖应先在目标系统/Python 版本查询及验证 wheel 兼容性，再锁定可用版本。

推荐部署顺序：创建持久 `data/`，创建私有 MinIO 桶并配置唯一随机密钥、强初始密码、上传上限及 HTTPS cookie；安装已验证依赖；构建前端；以 `PORT` 和 `WEB_CONCURRENCY` 启动；确认健康检查；登录后立刻改密码并替换示例软件。多 worker 使用 SQLite WAL；若以后需要高并发和多实例，应另行评估集中式关系数据库。

**备份**：停服务并复制 SQLite `data/`，使用 MinIO 的一致性方案同步私有桶对象；一并记录部署环境变量名和 MinIO 桶策略，但不要把密钥写入备份说明。**恢复**：恢复 SQLite 数据与对应 MinIO 桶对象，校验附件存在后启动并检查 `/api/health`、后台登录和资源下载。

## 6. 本次交付与验收范围

仓库提供 React/Mantine PC 暗色界面、软件目录/详情/历史版本/附件请求/私密反馈、社区审核/投稿/附件/回复、文章，以及后台统计和相关 CRUD；FastAPI、SQLite 与随机附件存储。应用默认不创建示例数据；仅在隔离开发环境显式设置 `SEED_DEMO_DATA=true` 时生成。前端生产构建和健康检查。验收应至少执行：

```bash
npm run typecheck
npm run build
python -m unittest tests_test_api -v
```

并实际验证：匿名不能查看待审内容或下载其附件；未登录不能写后台；后台跨站写请求必须通过 CSRF；URL 版本可独立交付；附件和反馈不在公开 API 泄露；生产静态构建可由后端托管。

# 部署要求

本文档只描述本项目的部署配置，不包含其他系统、示例凭据或临时文件路径。

## 运行环境

- Python 3.9 或更高版本（建议使用项目虚拟环境）。
- Node.js 20 或更高版本，用于构建前端。
- 生产环境使用 HTTPS、持久化磁盘和可靠的密钥管理。

## 安装、构建与启动

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm ci
npm run build
# 首次配置（已有 .env 时不要覆盖）：
cp -n .env.example .env
chmod 600 .env
# 编辑 .env，填写应用密钥和 COS 配置后再启动。
.venv/bin/python -m uvicorn backend.main:app --host 0.0.0.0 --port ${PORT:-8950}
```

部署平台请使用上面的 `uvicorn backend.main:app` 启动命令。`Procfile` 也已指向同一 FastAPI 入口。部署验收应请求 `GET /api/health`，确认返回健康状态。

## 必需配置

从 `.env.example` 复制为项目根目录 `.env`，填写真实值。后端启动时自动加载，部署平台已注入的环境变量优先，不会被 `.env` 覆盖。`.env` 已被 Git 忽略；不要提交、上传前端或分享密钥，生产中限制文件权限为 `600`，也可直接使用平台密钥管理：

- `SECRET_KEY`：生产环境使用随机生成且足够长的值。
- `ADMIN_PASSWORD`：仅用于首次创建管理员；密码必须为强密码。
- `DATABASE_URL`：默认 SQLite，例如 `sqlite:///./data/app.sqlite`。数据库文件必须位于持久化磁盘并加入备份策略。
- `UPLOAD_STAGING_DIR`：上传过程的短暂暂存目录，默认 `.upload-staging/`；它不是持久化文件存储，应用会在每次上传结束后清理其中的文件。
- `STORAGE_PROVIDER=cos`：推荐使用现有腾讯云 COS；必填配置见下节。不需要运行 MinIO 或 Docker。
- `STORAGE_PROVIDER=minio`：可选兼容模式，需要 `MINIO_ENDPOINT`、`MINIO_ACCESS_KEY`、`MINIO_SECRET_KEY`、`MINIO_BUCKET`；使用 TLS 时设置 `MINIO_SECURE=true`。未设置 provider 时保持旧行为，使用 MinIO。
- `MAX_UPLOAD_MB`：上传大小上限（单位为 MB）。
- 本地 MinIO 使用已运行的 Docker Desktop：执行 `./scripts/minio-dev.sh`，通过 `compose.minio.yaml` 拉取固定版本镜像并后台启动。API 为 `127.0.0.1:9000`，控制台为 `127.0.0.1:9001`，均不对局域网开放；数据和随机开发密钥分别保存在 git 忽略的 `data/minio-dev/`、`data/minio-dev.env`。首次启动需要 Docker 能访问 Docker Hub；拉取失败不代表服务已启动。不要把这组开发 root 凭据用于生产，生产应使用最小权限应用账号。
- 启动后端前，在同一 shell 中执行 `set -a; . ./data/minio-dev.env; set +a`，再按现有应用启动方式运行；不会自动加载该文件。控制台登录信息在该本地文件中，请勿提交或分享。
- 停止本地 MinIO：`docker compose --project-name duwuku-storage --env-file data/minio-dev.env -f compose.minio.yaml down`，不会删除本地对象数据。镜像版本固定用于本地联调，不代表已完成生产安全评估；部署前须重新评估受维护版本、更新与备份方案。

密码使用带随机盐的 PBKDF2-HMAC-SHA256 哈希存储。旧版无盐哈希仅用于兼容登录并在成功后升级。

## 对象存储（腾讯云 COS，推荐）

在已有存储桶中预留专用前缀，例如 `duwuku/`，无需手动创建目录。示例配置：

```dotenv
STORAGE_PROVIDER=cos
COS_REGION=ap-guangzhou
COS_BUCKET=your-bucket-1250000000
COS_PREFIX=duwuku/
COS_SECRET_ID=
COS_SECRET_KEY=
COS_SESSION_TOKEN=
```

- 桶名必须包含 APPID 后缀，地域必须与该桶一致；使用现有桶，不自动创建桶或更改桶策略。
- `COS_PREFIX` 必填，支持多层目录，不允许 `.`、`..` 或反斜杠。上传和下载都会加此前缀，数据库只记录相对对象键。沿用应用现有分类路径和随机文件名，不改变业务关联。
- `COS_SECRET_ID`、`COS_SECRET_KEY` 使用专用 CAM 子账号密钥，只允许访问该桶的指定前缀。需要 GetObject、PutObject、PutObjectACL，以及大文件分块上传所需的 InitiateMultipartUpload、UploadPart、CompleteMultipartUpload、AbortMultipartUpload、ListParts 权限；如需列出分块任务，再授予相应权限并限制范围。
- `COS_SESSION_TOKEN` 仅临时 STS 凭据需要；当前不会自动续期，过期前必须更新凭据并重启服务。
- 部署前确认桶及对象不允许匿名访问，桶策略不得向匿名用户授予此前缀读取权限。应用上传设置对象 ACL 为 private，但不能抵消桶策略的公开授权；应用不会读取或修改共享桶策略。
- COS 使用 HTTPS，下载仍经过网站现有权限检查，再返回五分钟有效的签名 URL。密钥不得放到前端、`VITE_*` 变量或日志中。浏览器通过后端上传和跳转下载，通常不需要配置浏览器直传 CORS。
- COSBrowser 仅辅助管理：直接上传的文件不会自动登记到网站；移动或删除网站对象会使关联失效。
- 生产缺少必需配置时拒绝启动，不会回退到本地持久化存储。启动检查只验证配置完整性，不证明凭据、权限和网络可用。
- 上线验收：通过网站上传小文件和大文件，验证下载内容；用不带签名的对象 URL 确认匿名读取被拒绝；验证过期链接不可用。存储、请求及公网下载流量按腾讯云计费。

切换 provider、桶名或前缀不会自动迁移旧文件。已有对象必须复制到新位置，并保留数据库相对键对应的路径，否则历史下载失效。备份配置后再切换。

### 可选 MinIO

设置 `STORAGE_PROVIDER=minio` 并填写上述 MinIO 配置。保持原有私有 bucket 上传及五分钟预签名下载逻辑，本地开发启动方式见上节。

## 代理、Cookie 与安全

- `TRUSTED_PROXY_CIDRS` 只填写实际反向代理的网段；只有来自这些网段的 `X-Forwarded-For` 才会影响记录的客户端 IP。
- 生产启用 `COOKIE_SECURE=true`，并通过 HTTPS 传输登录 cookie。
- 反向代理应限制上传请求体大小、启用 TLS，并只转发必要的请求头。
- 不要启用 `SEED_DEMO_DATA` 作为生产默认值；生产环境禁止演示数据种子。

## 演示数据

应用启动不会自动创建演示数据。仅在隔离的开发环境中显式设置 `SEED_DEMO_DATA=true` 后启动，或按项目提供的显式 seed 命令执行；生产环境会拒绝该配置。

## 持久化与备份

持久化 SQLite 数据库和私有 COS 专用前缀（或 MinIO bucket），并定期验证备份恢复。`.upload-staging/` 不是备份对象；升级代码前备份数据库和对象存储。应用进程应监听平台提供的 `PORT`（若部署平台要求），或显式传入 `--port`；不要依赖临时目录。
